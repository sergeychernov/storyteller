# F01.2 — API общего таймлайна

Серверная часть для milestone P0 в [product roadmap](product-roadmap.md). Готовы чтение таймлайна, перестановка сцен и атомарный перенос материалов. Адаптивный Web подключает перестановку сцен и перенос одного материала между сценами через drag-and-drop. Native Mobile и MCP сохраняют milestones P1 и P2.

## HTTP

Все операции требуют обычный Bearer token владельца истории. Контракты и ошибки включены в OpenAPI (`/docs`).

| Операция | Метод и путь | Результат |
| --- | --- | --- |
| Прочитать таймлайн | `GET /stories/{storyId}/timeline` | Тайминг сцен, общая длительность и предупреждения; `Cache-Control: private, no-store` |
| Задать порядок сцен | `PUT /stories/{storyId}/scene-order` | Полная обновлённая `Story` |
| Перенести материалы | `POST /stories/{storyId}/scenes/{sceneId}/materials/move` | Полная обновлённая `Story` |

Порядок:

```json
{
  "sceneIds": [
    "00000000-0000-4000-8000-000000000002",
    "00000000-0000-4000-8000-000000000001"
  ],
  "expectedRevision": 12
}
```

`sceneIds` содержит все текущие сцены ровно по одному разу. У пустой истории допустим пустой массив. Монтажный порядок хранится явно в массиве `Story.scenes` в JSONB; `sceneOrder` ответа таймлайна выводится из него. Дублирующей таблицы порядка, сортировки по ID/времени съёмки и миграции не требуется.

Перенос:

```json
{
  "materialIds": ["00000000-0000-4000-8000-000000000010"],
  "targetSceneId": "00000000-0000-4000-8000-000000000002",
  "targetIndex": 0,
  "expectedRevision": 13
}
```

- Исходная и целевая сцены должны различаться и принадлежать истории из URL. Для порядка внутри одной сцены остаётся существующий `PUT …/material-order`.
- `materialIds` — непустой массив без дублей. Все материалы должны находиться в исходной сцене; в целевую они вставляются в порядке запроса.
- `targetIndex` — позиция до операции: 0 означает начало, число материалов целевой сцены — конец. Неверный индекс не исправляется автоматически.
- Перенос сохраняет ID, оригинал, crop/rotation/trim, производное изображение, хеши и аудио/видеодорожки. Ключи файлов не переименовываются, даже если содержат ID прежней сцены. Копирования или задач удаления нет.
- Презентация обеих затронутых сцен сбрасывается по существующим правилам: одиночное фото получает свой renderer/focus/motion, несовместимые макеты снимаются; чужие сцены не меняются. Настроенная длительность сцены сохраняется.
- Опустевшая исходная сцена и её озвучка остаются; удалить её можно отдельно. После удаления исходной сцены перенесённые материалы продолжают принадлежать целевой.

## Конкурентные изменения и версии

Обе новые мутации требуют `expectedRevision`. Разрешены состояния `draft` и `ready`. Успех создаёт одну новую ревизию и переводит историю в `draft`; обновление обеих сцен сохраняется одним compare-and-swap JSONB, поэтому частичного переноса нет.

Проверяется как ревизия клиента, так и ревизия в момент записи. Повтор запроса со старой ревизией возвращает 409, даже если первая попытка успела завершиться. Клиент должен перечитать историю и согласовать намерение; слепой повтор с подставленной новой ревизией недопустим. Даже запрос неизменного порядка с актуальной ревизией создаёт новую ревизию.

Перестановка сохраняет независимые рендеры сцен и привязки озвучки по ID. Перенос меняет входы рендера двух сцен; история версий сохраняется, актуальность пересчитывается механизмом F05.1. Обе операции снимают `music.applied`, сохраняя сам аудиофайл. Полноценные версии мастера, микса и подтверждения подключаются в F04/F07.3/F05.2.

| HTTP | Код / причина |
| --- | --- |
| 400 | Неверная структура, UUID, индекс нецелый/отрицательный, отсутствующая ревизия или лишние поля |
| 401 | Нет действующей сессии |
| 404 | История недоступна; `scene_not_found` или `material_not_found` для отсутствующих участников переноса |
| 409 | `story_revision_conflict` или `story_not_editable` |
| 422 | `invalid_timeline_edit`: неполный/повторяющийся порядок, неизвестный ID в порядке, дубли материалов, та же сцена или индекс за границей |

## Длительность

Каждая запись `scenes` содержит `sceneId`, `index`, `materialIds`, `startSeconds`, `endSeconds`, `durationSeconds` и `durationSource`. Ответ привязан к `storyId` и `revision`.

- Фото и композиции используют настроенную длительность сцены. Это монтажный расчёт, а не подтверждение, что сложный renderer уже реализован или мастер проверен.
- Одиночное видео: конец trim минус начало на исходной временной шкале; без trim — `sourceDurationSeconds`, затем длительность видеодорожки. Этот же общий расчёт использует подпись длительности в текущем Web.
- Пустая сцена даёт 0 и предупреждение `empty_scene`; её условные пять секунд настройки не изображаются как готовое видео.
- Видео без достоверной длительности даёт `null` и `unknown_video_duration`. Общий итог и последующие абсолютные границы тоже `null`; длительности известных сцен остаются доступны. `knownDurationSeconds` — сумма известной части, нижняя граница длительности.
- Межсценовые эффекты ещё не реализованы: текущие стыки без перекрытия, `transitionOverlapSeconds: 0`. API не принимает фиктивные crossfade-параметры. Когда эффекты появятся вместе со сборкой, расчёт должен учитывать фактическое перекрытие; это остаётся частью незавершённой F01.2.
- Секунды нормализуются до шести знаков после запятой. Покадровая проверка готового мастера относится к F04/F05.2.

В `formatLimits` возвращаются справочные профили длительности YouTube: Shorts, стандартная загрузка и загрузка для подтверждённого аккаунта. Каждый содержит `maxDurationSeconds`, `requiresVerifiedAccount`, `status` (`within_limit`, `exceeded`, `unknown`), `excessSeconds` и `isLowerBound`. При неизвестном итоге известная часть уже может превышать лимит; тогда возвращаются превышение и `isLowerBound: true`.

Правила проверены 28.08.2026: [Shorts — до 3 минут](https://support.google.com/youtube/answer/15424877?hl=en); [стандартная загрузка — до 15 минут; подтверждённый аккаунт — до 12 часов либо 256 GB](https://support.google.com/youtube/answer/71673?hl=en). Ровно максимальная длительность допустима.

Это проверка длительности, не разрешение на публикацию: доступность канала, геометрия, размер файла и авторские права здесь не проверяются. Площадка не выбирается и не сохраняется; проверка выбранного формата подключается после F15.6. Предупреждения не блокируют монтаж, не удаляют материалы и не сокращают историю. Instagram/Telegram остаются в milestone P3.

## Варианты UI/UX для выбора

| Вариант | Сценарий | Компромисс |
| --- | --- | --- |
| A — текущий редактор | Лента сцен с drag-and-drop, общий хронометраж, выбор материалов и явный перенос в другую сцену | Минимум изменений существующего интерфейса; длинная история требует прокрутки ленты |
| B — монтажная доска | Обзор всех сцен карточками, порядок и перенос материалов без крупного предпросмотра | Лучше видна структура; для детального монтажа нужен возврат к редактору сцены |
| C — список на телефоне | Крупные строки сцен с отдельной touch-ручкой; стрелки вверх/вниз доступны с клавиатуры | Случайный тап не начинает перенос; для длинной истории нужна вертикальная прокрутка |

Реализованы A для desktop Web и C как адаптация Web для телефона. Сцена меняет позицию локально во время drag, а после отпускания отправляется один `PUT` полного порядка с исходной ревизией. Выбор сцены сохраняется по стабильному ID. Материал из нижней ленты можно перенести на карточку другой сцены: доступные цели подсвечиваются, материал вставляется в конец целевой сцены, и после успешного ответа эта сцена открывается. Drop на исходную сцену не создаёт мутацию. Ошибка откатывает оптимистичное изменение; при `story_revision_conflict` клиент перечитывает историю и явно сообщает о конфликте. B остаётся возможным отдельным режимом обзора. Это не реализация нативного Mobile.

Для всех вариантов: сохранять выбор по ID, обновлять UI из возвращённой `Story`, перечитывать тайминг после изменения ревизии; при 409 сохранять намерение пользователя, показывать конфликт и предлагать перечитать актуальное состояние. Перенос видео в композицию может изменить хронометраж и потребовать ещё не готовый renderer — это должно быть видно до применения. Превышение показывается рядом с общей длительностью, без обязательного выбора площадки и без автоматической обрезки.

## Проверка

Регрессии добавлены в существующие domain/API/PostgreSQL suites: перестановка и полнота порядка; перенос, сохранение файлов и версий; авторизация, ошибочные входы, stale revision и гонка при записи; хронометраж и предупреждения; OpenAPI. PostgreSQL проверяет сохранение после нового чтения, удаление опустевшей сцены и конкуренцию перестановки с переносом в изолированной тестовой базе.

Текущий общий прогон содержит 122 теста продукта (`yarn test`), включая чистые модели перестановки сцен и оптимистичного переноса материала без изменения исходного объекта. Ранее 15 PostgreSQL-тестов API прошли с отдельной временной БД; текущая локальная среда не предоставляет тестовую БД. Вывод общей длительности и предупреждений API в Web, а также межсценовые эффекты остаются незавершёнными.

Drag-and-drop проверен в браузере на 360 px и desktop. Для сцен: pointer-перенос первой сцены в конец, один API-запрос с `expectedRevision`, сохранение выбора по ID, перестановка стрелкой, откат и перечитывание при `409`. Для материалов: перенос из нижней ленты в другую сцену с `targetIndex` в конце, открытие цели после успеха, отсутствие запроса при drop на исходную сцену и восстановление при конфликте. Горизонтального переполнения нет.
