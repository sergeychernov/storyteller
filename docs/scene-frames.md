# Производный кадр сцены

## Назначение

`scene-frame` — lossless PNG последнего декодированного кадра базовой визуальной
композиции сцены. В него входят применённые crop/rotation/trim, а для фотографии —
положение анимации в конце сцены. Название сцены, титры, субтитры и другие
поверхностные слои исключены политикой `base-visual`.

Один и тот же артефакт используется в миниатюре таймлайна и в затенённых соседних
превью. Активная сцена сохраняет интерактивный preview, а неактивные сцены не
загружают полное исходное видео.

## Хранение и версии

- Worker сначала строит базовый визуальный MP4 по тому же рецепту, что и экспорт
  сцены, но в lossless H.264 (`QP 0`) без CRF-компрессии. Затем он выбирает
  последний индексированный кадр и сохраняет его в PNG без повторных потерь.
- PNG хранится отдельно от видео в S3-совместимом object storage по ключу
  `projects/{profileId}/{storyId}/scenes/{sceneId}/frames/{inputHash}-{attemptId}.png`.
- `inputHash` включает визуальные входы, параметры сцены, версию PNG-экстрактора,
  уровень сжатия и политику слоёв. Расположение объектов не участвует в версии.
- Готовый PNG получает SHA-256 реальных байтов. Изменённая сцена делает прежний
  кадр неактуальным, но точный возврат правок повторно использует прежнюю версию.
- При удалении сцены её PNG удаляется через ту же надёжную очередь object deletion,
  что MP4/M4A и исходные материалы.

Производный рендер другой сцены может добавить зависимость с ролью `scene-frame`.
Она содержит SHA-256 PNG и `inputHash` исходной сцены. Изменение исходного кадра
меняет fingerprint зависимого рендера и не позволяет переиспользовать устаревший
кеш; одинаковый неизменившийся кадр не запускает лишний пересчёт.

## API

- `POST /stories/:storyId/scenes/:sceneId/frames` — идемпотентно получить или
  поставить в очередь текущую версию.
- `GET /stories/:storyId/scenes/:sceneId/frames/:frameId` — проверить статус и
  актуальность.
- `GET /stories/:storyId/scenes/:sceneId/frames/:frameId/content` — получить PNG;
  устаревшая версия отвечает `409 scene_frame_stale`.

Все endpoints требуют владельца истории и отвечают с `private, no-store` при
чтении статуса или содержимого. Версии кадров не смешиваются со списком
пользовательских видео/аудио экспортов сцены.

## Текущая граница

Web создаёт PNG для поддержанных серверным рендерером сцен с одной фотографией
или одним видео. Серверные кадры многоматериальных коллажей появятся вместе с
композиторами F03.1/F03.2; до этого Web показывает placeholder и не подменяет
финальный кадр приближённым браузерным снимком.
